# Feedback Collector: устройство и вопросы для защиты

## Что сказать о работе

«В этой работе я создал веб-приложение на Go. Пользователь открывает страницу,
заполняет форму, а сервер проверяет запрос и сохраняет запись в срезе.
HTML формируется через `html/template`. После изменения сервер перенаправляет
браузер на главную страницу, где видны актуальные данные».

## Основные функции и конструкции

| Элемент | Для чего нужен |
| --- | --- |
| `main` | Создаёт `App` и запускает HTTP-сервер на порту 8080 |
| `NewApp` | Создаёт состояние, начальный счётчик ID и разбирает шаблоны |
| `Handler` | Регистрирует маршруты отдельного `http.ServeMux` |
| `homeHandler` | Создаёт снимок среза и передаёт его в шаблон |
| `aboutHandler` | Возвращает страницу о приложении |
| `parseForm` | Ограничивает размер тела и проверяет разбор формы |
| `render` | Генерирует HTML в буфере и записывает HTTP-ответ |
| `feedbackHandler` | Читает имя и текст, проверяет, добавляет отзыв и перенаправляет |
| `append(a.feedbacks, Feedback{...})` | Добавляет структуру в срез |
| `len(a.feedbacks)` | Вычисляет число опубликованных отзывов |
| `http.Redirect` | Отправляет 303 и адрес главной страницы |
| `sync.Mutex` | Не даёт параллельным обработчикам менять срез одновременно |
| `embed.FS` | Включает HTML и CSS внутрь программы при сборке |

## Вопросы преподавателя

### Что такое обработчик HTTP?

Функция вида `func(w http.ResponseWriter, r *http.Request)`.
`r` содержит метод, URL и данные запроса, а через `w` формируется ответ.

### Чем GET отличается от POST в этой работе?

GET получает страницу. POST изменяет данные. HTML-формы отправляют POST,
а переход по ссылке отправляет GET. Маршрутизатор возвращает 405 для
неподходящего метода и указывает разрешённые методы в заголовке `Allow`.

### Что означает `GET /{$}`?

Это точное сопоставление корневой страницы в `ServeMux` Go 1.22+.
Без `{$}` обработчик `/` может захватить неизвестные вложенные адреса.

### Что делают `r.ParseForm` и `r.FormValue`?

Первый разбирает форму и позволяет явно обработать ошибку разбора.
Второй возвращает значение поля по имени. Пустые значения дополнительно
проверяются после `strings.TrimSpace`, поэтому одни пробелы не проходят.

### Зачем проверка на сервере, если есть `required`?

Атрибут проверяется браузером. Его можно обойти прямым HTTP-запросом,
поэтому сервер сам проверяет все обязательные поля.

### Почему после формы возвращается 303?

303 сообщает браузеру, что результат нужно получить отдельным GET-запросом.
Так реализован Post/Redirect/Get. Обновление страницы не повторяет POST.

### Как Go передаёт данные в HTML?

`ExecuteTemplate` получает `PageData`. В шаблоне `{{range .Feedbacks}}` перебирает
срез, `{{if .Total}}` выбирает ветку, а `{{.ID}}` выводит поле текущего элемента.
`html/template` экранирует пользовательский текст, например `<script>`.

### Почему шаблоны разбираются один раз?

Они не меняются во время работы. Повторный разбор на каждый запрос не нужен.
`template.Must` немедленно останавливает запуск при ошибке шаблонов.

### Зачем получатель `a *App`?

Это указатель на общее состояние приложения. Обработчики изменяют исходный
срез и счётчик, а не копию структуры. `NewApp` позволяет создавать независимое
состояние для каждого теста.

### Почему перед отображением делается копия среза?

`append([]T(nil), a.records...)` создаёт отдельный массив элементов.
Копия строится под блокировкой, затем блокировка снимается. Шаблон читает
стабильный снимок, пока другие запросы могут менять исходный срез.
В коде вместо `T` и `records` используются конкретная модель и имя среза.

### Почему нужен Mutex?

`net/http` обрабатывает запросы параллельно. Одновременное изменение среза
и счётчика без синхронизации может привести к гонке данных и потерянным записям.
`Lock` закрывает доступ, `Unlock` освобождает его; `defer` выполняет освобождение
при выходе из функции. Это защита общего состояния внутри одного процесса.

### Зачем два поля, если можно хранить одну строку?

`Author` и `Message` имеют разный смысл. Их можно отдельно проверять и отображать.
`ID` идентифицирует запись независимо от одинакового текста у разных авторов.

### Почему нет удаления и редактирования?

Практическое задание требует упрощённый сбор отзывов без этих операций.

### Сохраняются ли данные после обновления и перезапуска?

После обновления — да, серверный процесс продолжает хранить срез.
После перезапуска — нет: база данных или файл не используются.
Все посетители видят общий список; отдельных учётных записей нет.

### Что проверяет тестирование?

`httptest.NewRequest` создаёт запрос, `httptest.NewRecorder` принимает ответ.
Тест вызывает настоящий маршрутизатор, проверяет HTTP-код, заголовки и HTML.
Последовательность запросов проверяет состояние после изменений и повторного GET.
Это автоматическая проверка серверной логики, а не визуальный тест браузера.

### Какие варианты развития возможны?

Добавить базу данных, пользователей и разделение их записей, защиту операций
изменения от CSRF и постраничный вывод при большом количестве данных.
В текущем учебном варианте сервер слушает только локальный адрес.
