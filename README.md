# Модуль 11. Практическая работа: Feedback Collector

Учебная работа по дисциплине **CSE5032 «Разработка веб-сервисов»**.  
Кафедра Программной инженерии, Институт Автоматики и информационных технологий.

## Цель работы

Освоить создание веб-приложения на Go: запустить HTTP-сервер, настроить маршруты,
обработать HTML-формы и сформировать страницы через `html/template`.
В неделях 9–10 ввод выполнялся в консоли; здесь пользователь работает в браузере,
а обработку данных выполняет сервер.

## Реализованные возможности

1. Форма принимает имя автора и сообщение.
2. Сервер удаляет крайние пробелы и проверяет оба поля.
3. Корректный отзыв получает уникальный ID и добавляется в `[]Feedback`.
4. Главная страница показывает ID, автора, текст каждого отзыва и их количество.
5. Обновление страницы сохраняет опубликованные отзывы в пределах одного запуска.

## Технологический стек

- Go 1.22 или новее; зависимости только из стандартной библиотеки.
- `net/http`: сервер, маршрутизатор, HTTP-ответы и перенаправления.
- `html/template`: HTML-страницы с автоматическим экранированием пользовательского текста.
- `embed`: шаблоны и CSS включаются в исполняемый файл.
- `sync.Mutex`: защита общего среза при параллельной обработке запросов.
- HTML и CSS: адаптивная форма и список записей без JavaScript.


## Модель данных

```go
type Feedback struct {
    ID      int
    Author  string
    Message string
}

type PageData struct {
    Feedbacks []Feedback
    Total     int
}
```

Срез хранится в `App`; `PageData` передаёт снимок данных в шаблон.
Счётчик `nextID` начинается с 1. Данные общие для посетителей одного экземпляра
приложения и сохраняются только до остановки процесса.

## HTTP-маршруты

| Метод | Маршрут | Действие | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/` | Форма, список отзывов и общее количество | 200 |
| POST | `/feedback` | Добавление отзыва | 303 → `/` |
| GET | `/about` | Информация о приложении | 200 |
| GET | `/static/style.css` | Стили страницы | 200 |

Изменения выполняются POST-запросами. GET по адресам изменения возвращает **405**
и не меняет данные. Неизвестный адрес возвращает **404**.
Некорректная форма возвращает **400** с понятным текстом ошибки.

## Как обрабатывается форма

1. Браузер отправляет поля формы методом POST.
2. `parseForm` проверяет разбор тела запроса и ограничивает его размер до 1 МиБ.
3. Обработчик получает поля через `r.FormValue` и проверяет значения.
4. Сервер изменяет срез под защитой `Mutex`.
5. `http.Redirect` возвращает **303 See Other** и `Location: /`.
6. Браузер выполняет GET `/`; сервер передаёт `PageData` в HTML-шаблон.

Такой порядок называется **Post/Redirect/Get**. Обновление итоговой страницы
повторяет GET, поэтому браузер не отправляет предыдущую форму ещё раз.

Атрибут `required` помогает в браузере, но сервер отдельно проверяет поля:
запрос можно отправить и без HTML-формы. Пользовательский HTML выводится текстом,
а не выполняется, благодаря `html/template`.

## Проверка через браузер

Следующая таблица — инструкция для самостоятельного повторения.
Автоматически проверенные результаты приведены ниже; ручная визуальная проверка
браузера в этот отчёт не включена.

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть `/` | Видны форма, пустой список и счётчик 0 |
| Отправить имя `Сахтай` и сообщение `Изучаю Go` | Отзыв #1 появляется, счётчик 1 |
| Отправить второй отзыв | Отображаются две записи, счётчик 2 |
| Пустое имя / пустой текст / одни пробелы | 400, запись не создаётся |
| Открыть `/about` | Информация о проекте |
| Обновить `/` | Обе записи остаются |
| Открыть `/feedback` адресной строкой | 405 Method Not Allowed |

## Проверка через PowerShell / cURL

При запущенном сервере, в отдельном терминале:

```powershell
curl.exe -i http://localhost:8080/
curl.exe -i -d "author=Student&message=Hello+Go" http://localhost:8080/feedback
curl.exe -i -d "author=&message=Hello" http://localhost:8080/feedback
curl.exe -i http://localhost:8080/feedback
curl.exe -i http://localhost:8080/about
```

Примеры предполагают свежий запуск сервера. После корректного POST ожидается
303; `curl.exe` без `-L` показывает само перенаправление. Для просмотра изменённого
списка выполните GET `/` отдельно.
